# Мультиагентная система для анализа файлов и данных

Семинар (30 минут): CrewAI + Claude. Агенты (маршрутизатор файлов, аналитик документов, аналитик таблиц,
автор отчётов) обрабатывают папку `data/` и собирают `output/report.md` с графиками в `output/charts/`.

## Структура

```
data/                      входные файлы (кладите свои сюда)
output/                    отчёты, ответы и графики (не попадают в git)
main.py                    точка входа
multiagent/
  config.py                пути, модель по умолчанию, тарифы
  schemas.py               схемы результатов агентов
  app/                     запуск
    cli.py                 аргументы командной строки и диалог
    runner.py              запуск, токены, стоимость
    compare.py             сравнение моделей
  crew/                    команда агентов
    agents.py              роли агентов и модель
    builder.py             задачи и сборка команды
  routing/                 выбор файлов под вопрос
    catalog.py             карточки файлов для маршрутизатора
    selection.py           выбранные файлы
  guardrails/              проверки результатов
    validation.py          JSON по схеме, покрытие файлов, выбор маршрутизатора
    report.py              разделы и графики отчёта, проверка чисел
    facts.py               числа аналитиков и сверка с отчётом
  tools/                   инструменты агентов
    files.py               чтение документов (только data/)
    tables.py              анализ таблиц (pandas)
    charts.py              графики (только output/charts/)
```

## Запуск

Команды выполняются из корня проекта.

```bash
uv sync
# впишите ANTHROPIC_API_KEY в .env
.venv/bin/python main.py                 # последовательно, подробный лог
.venv/bin/python main.py --parallel      # аналитики работают одновременно
.venv/bin/python main.py --ask "Какие города приносят больше выручки?"   # один свой вопрос
.venv/bin/python main.py --ask "..." --files sales_2026.xlsx strategy_2026.md   # вручную выбрать файлы
.venv/bin/python main.py -i              # диалог: вводите вопросы по одному, ответы в output/answer_N.md
.venv/bin/python main.py --model anthropic/claude-sonnet-5-5
.venv/bin/python -m multiagent.compare # Haiku 5.5 и Sonnet 5.5 на одних данных (тратит токены)
```

В конце каждого запуска печатаются время, токены и оценка стоимости (тарифы в `multiagent/config.py`).
Модель по умолчанию задаётся в `.env` (`MODEL`).

## Что показываем

| Тема | Где |
|---|---|
| Роли агентов и инструменты | `multiagent/crew/agents.py`, `multiagent/tools/` |
| Задачи, зависимости, параллельный запуск | `multiagent/crew/builder.py` (`context`, `async_execution`) |
| Структурированный вывод + guardrails с повтором | `multiagent/schemas.py`, `multiagent/guardrails/` |
| Графики (единственный инструмент записи, только в `output/charts/`) | `multiagent/tools/charts.py` |
| Безопасность: prompt injection | `data/vendor_email.txt`, `multiagent/tools/files.py` |
| Токены и стоимость, сравнение моделей | `multiagent/app/runner.py`, `multiagent/app/compare.py` |

## Заметки

- Схему результата проверяем сами (`multiagent/guardrails/validation.py`), а не через `output_pydantic`: в CrewAI он шлёт
  принудительный `tool_choice`, который Sonnet 5.5 и Opus 5.5 отклоняют (HTTP 400).
- У агента с ровно одним инструментом CrewAI тоже форсирует `tool_choice`. Давайте таким агентам
  два и более инструментов.
- `temperature` и `top_p` не задаём: Sonnet 5.5 и Haiku 5.5 отвергают нестандартные значения.
- Защита от prompt injection многослойная: содержимое файлов оборачивается в `<document>`, агент
  инструктирован не выполнять команды из файлов и помечать их (`injection_detected`), путь чтения
  ограничен `data/`. Это снижает риск, но не гарантирует защиту.
- Демо-файл `vendor_email.txt` содержит вредную инструкцию намеренно. Уберите его для «чистого» прогона.
- `data/orders.csv`: два выброса и один пропуск заложены специально.

## Свои файлы и вопросы

Кладите файлы в `data/`: `.txt`, `.md`, `.pdf` (с текстом), `.docx` (текст и таблицы), `.csv`, `.xlsx`
(каждый лист разбирается отдельно). Без вопроса обрабатываются все файлы. С вопросом (`--ask`, `-i`)
сначала работает агент-маршрутизатор: по каталогу файлов (`multiagent/routing/catalog.py`: начало текста документов, листы и
колонки таблиц) он выбирает нужные файлы, причины печатаются как `[router] файл: причина`. Выбирает с
запасом, но может ошибиться; `--files` задаёт файлы вручную и отключает маршрутизатор. Аналитики
обрабатывают только выбранные файлы, автор отвечает на вопрос в разделе «Резюме».

| Файл | Что внутри |
|---|---|

| `marketing_campaigns.xlsx` | листы «Кампании» (48 строк) и «Недели»; аномалии в показах, выручке, бюджете |
| `hr_staff.xlsx` | листы «Сотрудники» (142 строки) и «Текучесть» |
| `support_tickets.csv` | 900 обращений с выбросами по времени решения, пропусками CSAT и дублями |
| `strategy_2026.md`, `customer_interviews.txt`, `quarterly_report_q3.docx`, `supplier_contract.pdf` | длинные документы |
| `orders.csv`, `meeting_notes.md`, `customer_feedback.txt` | маленькие файлы для быстрых прогонов |
| `vendor_email.txt` | демо prompt injection; уберите для «чистого» прогона |

Полный прогон на всех файлах: около 2 минут и $0.07 на Haiku 5.5; вопрос с маршрутизатором по части файлов обычно вдвое дешевле. Для быстрых тестов оставьте в `data/` только маленькие файлы.
